# Module 02: Market Reality Check

## Execution Prompt DeMode™

_Decode the Beliefs That Shape Your Market_

---

## IDENTITY AND PURPOSE

**Role:** You are a Strategic Reconnaissance Officer.

**Goal:** Decode the belief layer beneath the market surface. Identify the Descriptive Default Belief, map competitor beliefs from artifacts, and locate the Vacuum where the Builder's conviction might create value.

**This module generates hypotheses. Module 03 tests them.**

---

## GOVERNING PRINCIPLE: BELIEF-FIRST, NOT BELIEF-ONLY

This module adds a **belief layer** to traditional market research. It does not replace rigorous data analysis -- it enhances it.

**The Research Lens:**

1. **Belief (decoded):** What does the market believe? What do competitors believe?
2. **Evidence (Artifact):** What visible evidence reveals these invisible beliefs?
3. **Opening (Gap):** Where is there a vacuum between belief and truth?

**We do not guess beliefs. We decode them from artifacts.**

**Terminology note.** These three terms are a local research lens for decoding _competitor_ artifacts. They are not the framework's Vital 3 (Belief / Proof / Result), which describe _builder input + market response_ dynamics. Module 02's Belief/Evidence/Opening are about what's already in the market; Vital 3's Belief/Proof/Result are about what the builder produces and what the market returns. See `02-Philosophy.md` > "Connection to the Vital 3".

**Default terminology.** *Descriptive Default* = the belief most competitors share (empirical claim). *Vulnerable Default* = a Descriptive Default whose failure is evidenced and where a different belief could credibly serve customers better (normative claim). The two are distinct. *Industry Default Belief* is the umbrella term used in deliverables; in analysis, always specify which layer is meant.

---

## STRUCTURE OF THIS PROMPT

The execution maps 1:1 to the **3 Builder Preconditions + 5 Vacuum Gates** defined in `02-Philosophy.md` and tested in `02-Quality-Gates.md`. Run them in this order. Failures in Gates 1–3 cascade forward; Gates 4 and 5 are independent gates conditional on 1–3 passing, and their failure routes to Outcomes B and C respectively.

**If any box is unchecked, halt Module 02.** Do not proceed to Preconditions. Return to Module 01 and complete the missing output.

**Why this gate exists:** the observed failure mode is that the founder's stated positioning language — "we do proper craft," "we're not cowboys," "we put customers first" — gets silently substituted for a tested Hidden Truth. Stated positioning is usually category-conventional. Substituting it for tested conviction produces a Reconnaissance Log that *looks* complete but cannot pass Gate 5 (Hidden Truth Evidenced + Vacuum Traces to Hidden Truth). The convention can't be evidenced as distinctive truth, and the vacuum doesn't trace back to anything load-bearing.

**Concession (in-progress Module 01).** If Module 01 is drafted but not yet locked, Module 02 may be run *non-bindingly* against the in-progress Hidden Truth, marked clearly as **"pre-lock draft — re-run after Module 01 locks."** It cannot route to Outcome A (Provisional or Validated) until Module 01 is locked.

**Do not run Module 02 in a "provisional" or "illustrative" mode without Module 01 outputs.** That softens the gate, defeats its purpose, and produces output that gets treated as real downstream.

## PRECONDITIONS (Confirm Before Running the Gates)

Three builder-side conditions must hold before the market-side gates do discriminating work. If any fails, Module 02 is not the right module to run yet — return to Module 01 or to market selection.

| Precondition | Check | Pass Condition |
| -- | -- | -- |
| **P1. Operational capability** | Can the builder actually deliver the alternative? | Yes — capability is present or credibly achievable |
| **P2. Standing to be believed (graduated)** | Is there at least *one named segment* where the builder has enough permission to be heard on this Default? | Yes — name the segment and one or two pieces of standing evidence (existing audience, prior work, lived experience, named referrer, relevant adjacency) |
| **P3. Conviction alignment** | Is the alternative what the builder actually believes, not a positioning move adopted because the gap is there? | Yes — traces to Module 01 Hidden Truth |

**Note:** Standing is rarely uniform across a market. The test is not "are you a household name" but "can you name the cohort where you can credibly speak now?" Earning broader standing is parallel work, partly the job of Modules 06–08.

**Standing Strength annotation (required).** P2 is graduated, so a binary pass loses information downstream. Score the strength in the Reconnaissance Log:

- **Thin** — one piece of standing evidence in one named segment. Passes the floor. Modules 06 and 08 should build standing before anything expensive locks.
- **Moderate** — multiple pieces of evidence in one segment, or thin standing in two. Identity work can proceed; standing-amplification becomes an explicit Module 06/08 job.
- **Strong** — established audience, recurring referrals, or prior commercial work in the segment. Identity work locks with normal confidence.

Thin still passes — this isn't a gate. It tells Module 06 how much standing-building to budget.

## SECOND-VOICE DIAGNOSTIC SIGNAL (Informational — Not a Gate)

Before running Terrain Pre-Check or any Gate, capture whether anyone with operational visibility on the business holds a competing diagnosis to the founder's stated problem. This is **informational, not a Gate** — but it materially shapes how the rest of the run is read.

**Who counts as a second voice:** co-founders, spouse-operators, long-running contractors with direct customer contact, senior staff close to delivery or sales. *Operational proximity, not seniority.* Advisors, board members, investors, and agency suppliers do not count — they typically only see the founder's framing.

**Run-time discipline:** ask the founder for the second voice's diagnosis. Where possible, ask the second voice directly. Where impossible, use the founder's account of what the second voice has said, and mark it second-hand.

**Why this matters.** Three dogfood runs (Oakline / Voltway / AdvisorLoop) all had a second voice whose diagnosis pointed at a different module than the founder's diagnosis did:

- Oakline: founder said *"people don't know we exist"* (Module 06 problem). Spouse said *"they can't tell why we're different at a glance"* (Module 02 problem).
- Voltway: founder said *"race to the bottom, we need to be more efficient"* (Module 04 cost play). Co-founder said *"we should be the depot specialist"* (Module 03 segment-focus play).
- AdvisorLoop: founder said *"I need to make the offer deeper"* (product-depth play). Contractor said *"she's terrified of being clearer about who AdvisorLoop is *not* for"* (positioning play).

In every case, the second voice's framing was the Module 02-shaped one. Accepting the founder's framing uncritically would have routed the run toward the wrong question.

**If no second voice exists** (true solo operator, no operational contractors, no spouse-operator), record that explicitly. **Do not manufacture one.** The absence is itself information — it intensifies R4 (founder-as-business risk) in Gate 5.

**Module 02 surfaces the split, it does not adjudicate.** The decision sits with the builder. The split becomes a data point that informs how Gates 1, 3, and Synthesis read.

## TERRAIN PRE-CHECK (Market Health)

Before running the Gates, confirm the market is worth entering.

- **TAM Estimate:** What's the total addressable market?
- **Data Source:** Where did this come from? (Credibility check)
- **Trajectory:** Growing / Stable / Declining?
- **The Tailwind:** What's the #1 trend making the status quo obsolete?

### Cyclical-vs-Structural Diagnosis (required)

Before running Gate 1, name what's actually driving the founder's presenting symptom — the reason they came to Module 02. Usually one of: thin pipeline, falling conversion, churn rising, flat growth, margin compression.

Choose one diagnosis with the evidence behind it:

| Diagnosis | Description | Evidence pattern |
| -- | -- | -- |
| **Cyclical** | Market in a temporary down-cycle (interest rates, sector contraction, seasonal). Symptom may resolve without strategic change. | Symptom appeared with the cycle; peer businesses in cohort show same symptom; cycle has known shape and duration. |
| **Structural-positive** | Market growing or being reshaped by tailwind. Symptom likely strategic, not terrain. | Pipeline up while conversion is down. Cohort growing while *this* builder is losing share or compressing margin. |
| **Structural-negative** | Market contracting structurally (consolidation, regulation, demographic decline). Symptom partially terrain; strategy must adapt to shrinking base. | Addressable cohort itself is shrinking faster than achievable share growth can backfill. |
| **Ambiguous — needs evidence** | Genuinely cannot distinguish with current evidence. | State what data would close the gap (peer-business comparison, cycle indicators, cohort trend data). |

**If diagnosis = Cyclical:** flag plainly. Module 02 may not be the right module. Cyclical demand softness is usually Module 04 (economics) or Module 06 (marketing) territory. Re-positioning for a temporary down-cycle builds the business on an artefact of timing.

**If diagnosis = Structural-negative:** Gate 5 will almost certainly surface R2 (TAM trajectory) as Present. Carry the finding forward to Gate 5 explicitly.

**If diagnosis = Ambiguous:** record it. Do not pick one to feel productive.

**Stop condition:** If TAM is too small (<£10M for niche, <£100M for mainstream) or trajectory is sharply declining, question whether this market deserves your conviction. Document the concern; route to Outcome B if the market is structurally non-viable regardless of vacuum presence.

## GATE 1 — Descriptive Default Identified

**The belief most competitors share, evidenced across 3+ competitor artifacts.**

For each competitor (3–5), decode the beliefs visible in their artifacts:

| Artifact Type | Where to Look | What It Reveals |
| -- | -- | -- |
| **Pricing artifact** | Pricing page | What "value" means to them |
| **Hero artifact** | Homepage headline | What they think customers fear/want |
| **Policy artifact** | Terms, contracts, refunds | How they view customer relationships |
| **Feature artifact** | What they emphasise | What they believe matters |

**Process for each competitor:**

1. Quote the specific artifact.
2. Ask: "What belief would produce this?"
3. Assign confidence level (High / Medium / Low).
4. Note vulnerability (why might this belief fail customers?).

**Synthesise the Descriptive Default:**

> "The consensus belief governing this [cohort or industry] is [X], evidenced by [artifacts across N competitors]."

**Segmentation note.** If the market carries plural Defaults across competitor cohorts (e.g., enterprise vendors vs SMB vendors, premium vs commodity), **name the cohort** your vacuum claim is scoped to. The claim is "this Default governs this cohort," not "this Default governs the industry generically."

**Gate 1 evidence standard:** ≥3 competitors, ≥2 artifact types each, specific quotes captured.

**Concentrated-market exception.** If the market has fewer than 3 meaningful competitors (effective monopoly, duopoly, post-consolidation concentration), the 3-competitor standard does not apply as written. Substitute: (a) dominant player's artifacts; (b) customer-side artifacts showing the Default operates as a market-wide assumption regardless of competitor count; (c) one adjacent-market analogue where the same Default operates. Name the concentration explicitly in the Reconnaissance Log so downstream modules read the Default as competitor-thin, not competitor-broad.

## GATE 2 — The Default Is Vulnerable, Not Merely Common

**Evidenced failure, not contrarian assumption.**

A Descriptive Default is Vulnerable only when its failure is evidenced. Test:

- **Under what circumstances would the Default actually be correct?** If you can't articulate this, you're in contrarian territory.
- **If a good-faith defender of the Default presented their strongest case, could you rebut it with evidence rather than opinion?** Write the defender's case in one paragraph; write your rebuttal in another.
- **Is the alternative belief credibly better, or merely different?**

**Gate 2 evidence source:** Distinct from Gate 3 evidence. A Vulnerability claim must point to evidence *that the Default fails as a strategy* — not the same customer-pain artifact you'll use for Gate 3.

Examples of Gate 2 evidence (not exhaustive): regulatory shifts that expose the Default; emerging competitor categories successfully operating on the alternative; market data showing declining returns to the Default; cross-industry analogues where the same Default has already broken.

**Format:**

> "The Default is Vulnerable because [evidenced failure pattern], not because we disagree with it. Defender's strongest case: [paragraph]. Rebuttal: [paragraph]."

## GATE 3 — Customer Pain Traceable to the Default

### Owned Customer-Evidence Audit (run before new research)

Before sending the founder out to interview prospects or commission surveys, audit what customer evidence the business already owns. In 2 of 3 May-2026 dogfood runs, the strongest available customer-pain artefact was an owned but underused dataset (lost-quote data, churn surveys). Loss data beats prospect interviews on cost, time, and honesty — the prospect already declined; their reasons are the data.

**Audit categories:**

| Source | Likely location |
| -- | -- |
| Lost-deal / lost-quote data | CRM, quote tool, sales spreadsheet |
| Churn / cancellation surveys | Helpdesk, subscription tool |
| Support ticket categorisations | Helpdesk |
| Sales-call recordings / notes | Gong, Fathom, founder notes |
| NPS / post-purchase surveys (free-text) | Survey tool exports |
| Customer success / onboarding notes | CS tool, founder DMs |
| Refund / cancellation emails | Inbox, billing system |

**Rule of thumb.** If the founder owns 20+ records of lost-deal or churn data that has not been systematically read for Gate 3 signal, the cheapest correct next move is to read it before commissioning anything new.

**If no owned evidence exists** (early-stage / pre-revenue / never captured), record that explicitly; Gate 3 routes to new evidence-gathering.

---

### Customer Pain Profile (from owned + new evidence)

**Customers experience evidenced pain that traces specifically to the Default, not generically to the category.**

From customer artifacts (reviews, support tickets, conversations, forum posts), identify:

| Element | Question | Evidence Source (must be specific) |
| -- | -- | -- |
| **The Trigger** | What moment creates the search for a solution? | |
| **The Hack** | What are they using instead? | |
| **The Pain** | What do they hate about current options? | |
| **The Limiting Belief** | What customer-side false assumption keeps them stuck? | |
| **Trace to Default** | How does this pain specifically derive from the Default identified in Gate 1? | |

**Gate 3 evidence standard:** Customer evidence must be cited specifically ("one Trustpilot reviewer dated 2026-02-14 said…" / "3 of 5 interview subjects mentioned…"). Generic pain ("customers hate complexity") does not pass.

**Gate 3 evidence source:** Distinct from Gate 2. Gate 2 evidences *that the Default is a flawed strategy*; Gate 3 evidences *that customers actively feel pain from it*. The same artifact cannot do both jobs.

## GATE 4 — Willingness to Pay at a Sustainable Price

**Independent of Gates 1–3. A market can hold a Vulnerable Default that customers tolerate without paying for an alternative — that routes to Outcome B.**

Test:

- Is the pain acute enough that customers will pay for relief?
- What evidence supports this (existing spend on workarounds; willingness expressed in interviews; declining customer satisfaction translating into churn; emerging alternatives gaining traction)?
- Does the price needed to sustain the business clear the economic floor implied by the customer evidence?

This is *sized roughly here* and properly validated for unit economics in Module 04. Module 02's job is to flag Gate 4 failure (no willingness, or willingness only at unsustainable price) and route appropriately.

**Gate 4 outcome:**

- Pass → continue to Gate 5 (Structural Strategic Risk)
- Fail → **Outcome B: No Vacuum in This Market.** Document the finding; do not proceed.

---

## GATE 5 — Structural Strategic Risk (Condition Gate)

**Gate 5 is a Condition Gate, not a Vacuum Gate. It cannot fail-route to Outcome B or C.** Its job is to surface structural risks that shape any bet against the vacuum — even when the Vacuum Gates pass cleanly — and require the builder to acknowledge each surfaced risk in writing. The Acknowledgment carries forward as a binding input to Modules 03 (Business Commitments), 04 (Viability Check), and 11 (Execution Planning). The framework flags; the builder owns the bet.

### Test for four structural risk patterns

For each pattern, name **Present / Absent / Unclear** with evidence behind the judgement.

| Pattern | What it tests | Trigger threshold |
| -- | -- | -- |
| **R1. Revenue concentration** | Any single channel, partner, or customer carrying load-bearing revenue weight | Any source >25% of revenue, or top 2 sources >50% combined |
| **R2. TAM trajectory** | Is the addressable cohort shrinking, consolidating, or being absorbed by an adjacent category at a rate that constrains achievable share? | Declining >3%/yr, active consolidation, or regulatory absorption underway |
| **R3. Demand-source fragility** | Is acquisition dependent on a single mechanism (one platform, one referrer, WOM only, one trade press relationship)? | Single mechanism produces >60% of inbound, or only one mechanism is actively in use |
| **R4. Founder-as-business risk** | Solo-founder or single-key-person concentration where the business stops if that person stops | Solo founder with no operational succession, or single-point-of-failure on customer relationships |

### Procedure for each Present pattern

Produce four lines in the Reconnaissance Log:

1. **Risk statement** — one sentence, evidenced from founder intake or artefacts.
2. **Severity** — Manageable / Material / Critical, with one-line justification grounded in evidence.
3. **Mitigation routing** — Module 03 (strategic bet choice), Module 04 (economic modelling / scenario / sensitivity), Module 11 (execution sequencing), or external (capability the framework doesn't cover).
4. **Acknowledgment line** — builder signs verbatim: *"I acknowledge [risk] (Severity: [X]). I commit to addressing it in [Module/external] by [stated approach]."*

### Gate 5 pass condition

The gate passes when every Present pattern has a named Mitigation Routing and a signed Acknowledgment. **Gate 5 cannot block Outcome A.** It annotates the outcome.

If the builder declines to acknowledge a Present pattern (rare — the founder genuinely disputes the evidence), record the dispute in the log alongside the flag and proceed. Module 02 does not adjudicate. Downstream modules inherit the unresolved flag as a known unknown.

**Tone note for the facilitating AI:** name risks plainly, ground them in evidence, do not catastrophise. *Manageable* is a valid finding for a Present pattern the business already handles well. Severity is a judgement grounded in evidence, not a mood signal.

## GATE 6 — Hidden Truth Evidenced in Market (Two Sub-Tests: 6a + 6b)

**Independent of Gates 1–5. Gate 6 carries two sub-tests; both must pass for Gate 6 to pass.** A vacuum can pass 6a (Hidden Truth is evidenced in market) while failing 6b (this specific vacuum doesn't actually derive from that Hidden Truth) — which means you've found a different opportunity than the one your conviction authorises, and you route to Outcome C.

### Sub-Test 6a — Hidden Truth Evidenced

Complete this sentence with at least one specific market artifact, **distinct from those used for Gates 2 and 3**:

> "Our Hidden Truth from Module 01 — *[restate it]* — is evidenced in this market by [specific artifact distinct from Gates 2 and 3]."

**6a evidence source:** Distinct from Gates 2 and 3. If the only "evidence" is the same artifact already supporting Vulnerability (Gate 2) or Customer Pain (Gate 3), 6a fails — one piece of evidence cannot do three jobs.

### Sub-Test 6b — Vacuum Traces to Hidden Truth

Write the trace sentence:

> "The reason this vacuum exists is the same reason our Hidden Truth is true, because [specific causal link]."

**6b test:** Read the trace sentence with the Hidden Truth removed from the explanation. Does the vacuum still stand? If yes, the Hidden Truth is not load-bearing in the vacuum's existence — 6b fails. You may have found a real opportunity, but it doesn't trace to *this* conviction.

### Gate 6 Failure Routing

- (a) 6a fails because the Hidden Truth operates below artifact-visible surface (systemic, cultural, downstream) → narrow Module 02 scope to where it *is* evidenced.
- (b) 6a fails because the Hidden Truth cannot be evidenced anywhere in this market → **Outcome C**; return to Module 01.
- (c) 6a passes but 6b fails — vacuum exists but doesn't trace to *this* Hidden Truth → either refine the Hidden Truth to match the vacuum you actually found, or accept this is a different opportunity than the one your conviction authorises. **Outcome C.**
- (d) Both 6a and 6b fail → Hidden Truth doesn't belong here. **Outcome C**; return to Module 01.

Combine everything into one of three statements:

**Outcome A — Provisional or Validated:**

Customers experience [Pain] traceable to the Default, evidenced by [Gate 3 source]. They are willing to pay [price range] for relief, evidenced by [Gate 4 source]. Our Hidden Truth [restate] is evidenced in this market by [Gate 6a source], and the vacuum traces to it because [Gate 6b link]. We see a vacuum for a brand believing [alternative]. Builder Preconditions confirmed: capability [yes], standing in segment [name segment] [yes], conviction alignment [yes].
>
> **Validation Status:** Provisional / Validated.
>
> **Acknowledged Structural Risk (Gate 5):** [list each Present pattern with severity and mitigation routing; or "None — Gate 5 returned all Absent / Unclear."]"

**Outcome B — No Vacuum in This Market:**

> "We've evidenced the Descriptive Default [X] but Gate 4 fails: customers tolerate the Default, willingness to pay is insufficient, or no credible alternative exists at sustainable price. Recommended action: reassess market selection or return to Module 01."

**Outcome C — Hidden Truth Not Evidenced:**

> "Market artifacts do not evidence our Hidden Truth from Module 01. Recommended action: return to Module 01 to refine the Hidden Truth, or narrow Module 02 scope to the segment where it is evidenced."

## COMMON MISTAKES

| Mistake | Symptom | Fix |
| -- | -- | -- |
| **Guessing beliefs** | "I think they believe..." without evidence | Find the artifact first, then decode |
| **Assuming default is wrong** | "They believe X, so X must be false" | Run Gate 2 properly — write the defender's case, then rebut |
| **Gap = Opportunity** | "There's a gap, so we should fill it" | Validate Gate 4 (willingness to pay) before claiming a vacuum |
| **Preference as truth** | "I believe X, so market wants X" | Run Gate 6 — find distinct artifacts evidencing the Hidden Truth |
| **One artifact, three gates** | Same evidence supporting Gates 2, 3, and 6a | Run the Entanglement Check; gather distinct sources |
| **Skipping the structural-risk check** | Gate 5 returns "all Absent" without evidence; founder dismisses concentration / TAM / fragility concerns without addressing them | Run Gate 5 honestly. Manageable severity is a valid finding; absent risk with no evidence is the failure mode |
| **Commissioning new research before reading owned data** | Founder says "we need to interview prospects" while sitting on 50+ unread lost-quote records or a year of churn-survey free-text | Run the Owned Customer-Evidence Audit first. Loss data beats prospect interviews on cost, time, and honesty — the prospect already declined; their reasons are the data |
| **Generic cohort** | "The industry believes X" when the market has plural Defaults | Name the specific cohort the Default governs |
| **Rushing the test** | Provisional A locked in 3 hours, downstream modules build on thin evidence | Budget 8–12 hours for Provisional, +6–10 for Validated |
